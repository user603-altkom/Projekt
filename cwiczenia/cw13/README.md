# Ćw. 13 — Zostaw procedurę zamiast „zapytaj Franka”

**Dzień 3, 9:30–10:00 · 30 min · Copilot**

Z procedury uzgadniania raportu z ćw. 07 zrób skill `.github/skills/uzgodnienie/SKILL.md`. Użyj YAML frontmatter z `name: uzgodnienie` oraz konkretnym `description`, kiedy go stosować. Procedura: reprodukcja → porównanie sum → lista dotkniętych ID → przyczyna → minimalna zmiana → kontrola. Zapisz, czego nie wolno traktować jako dowodu.

1. Napisz procedurę na podstawie własnego przebiegu; jeśli utknąłeś, użyj powyższych sześciu kroków.
2. W nowej sesji opisz objaw bez wymieniania nazwy skilla. Sprawdź ślad jego załadowania; jeśli brak, popraw opis lub wywołaj jawnie. Automatyczny wybór nie jest gwarantowany.
3. Po naprawie z dnia 2 wynik może już być zgodny. Wtedy poprawnym zachowaniem jest potwierdzenie zgodności, bez wymyślania usterki. Nie przywracaj uszkodzenia tylko dla demonstracji.
4. Partner wykonuje procedurę i wskazuje krok, którego nie umiałby powtórzyć.

**Gotowe:** poprawny plik, zaobserwowane użycie, wynik z dowodem. **Rozszerzenie:** recenzent z narzędziami wyłącznie do odczytu. Nie dawaj mu dowolnego terminala — terminal potrafi zapisywać pliki mimo braku narzędzia „edit”. Sprawdź odmowę zapisu na osobnej kopii.

Potem prowadzący pokazuje hook (8 minut). Nie implementujemy wszyscy strażnika ścieżek na Windowsie. Instrukcja mówi co robić, skill jak wykonać procedurę, hook uruchamia kod w zdarzeniu. Każdy mechanizm ma własny zakres działania. Superpowers to zestaw skilli i workflow, nie serwer MCP; oglądamy jako rozszerzenie.
