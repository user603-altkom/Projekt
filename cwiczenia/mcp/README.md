# Dokumentacja na żądanie: Context7 i CLI

**Dzień 3, 11:40–12:00 · 20 min · demo + krótka próba**

Zadanie: sprawdź w dokumentacji Vitest użycie `test.each` w wersji z `package-lock.json`, zanim dopiszesz parametryzację testu. Zapisz wersję, fragment źródła i działające polecenie testu.

Prowadzący pokazuje Context7 w Copilot Agent: `resolve-library-id`, potem `query-docs`. Wspierane podłączenie: rozszerzenie `Upstash.context7-mcp`, serwer widoczny w „MCP: List Servers”. Instalacja tylko w zatwierdzonym środowisku; konfigurację przygotuj przed blokiem. Nie wysyłaj fragmentów firmowego repo do publicznego serwera.

Porównaj: Context7 dostarcza fragment dokumentacji; `npm test` uruchamia lokalny test. MCP jest interfejsem udostępniania narzędzi, CLI sposobem wywołania programu. Mogą robić różne lub podobne rzeczy; MCP nie jest z definicji lepsze ani oszczędniejsze tokenowo. Znaczenie ma zawartość wyniku, uprawnienia i obsługa błędów.

**Gotowe:** źródło i wersja oraz test uruchomiony lokalnie. **Plan B:** dokumentacja producenta w przeglądarce i ten sam test; cel ćwiczenia zostaje. **Rozszerzenie:** porównaj wielkość i przydatność odpowiedzi z szerokiego i zawężonego pytania.

Źródło: https://context7.com/docs/clients/vscode (sprawdzone 20.09.2026).
